# نظام CRM لشركة سياحة — الخطة

واجهة عربية كاملة من اليمين لليسار، نسخة تجريبية ببيانات جاهزة أولاً، ثم الربط مع واتساب وموقع ووردبريس.

## المرحلة الأولى: الداشبورد (هذه المرحلة)

**الصفحة الرئيسية (لوحة المؤشرات)**
- بطاقات: إجمالي المبيعات، عدد الحجوزات، عملاء جدد، نسبة تحويل الفرص
- رسم بياني للمبيعات شهرياً + أفضل الباقات مبيعاً
- آخر الحجوزات وآخر المتابعات المطلوبة اليوم

**الباقات السياحية**
- قائمة بالباقات: الاسم، الوجهة، المدة، السعر، عدد المقاعد المتاحة، الحالة (متاحة/مكتملة/منتهية)
- إضافة وتعديل باقة، وبحث وتصفية حسب الوجهة والحالة

**العملاء**
- قائمة العملاء: الاسم، الجوال، البريد، المصدر (واتساب/الموقع/مباشر)، عدد الحجوزات، إجمالي ما أنفقه
- صفحة العميل: بياناته، حجوزاته السابقة، وسجل المحادثات والملاحظات

**الحجوزات والمبيعات**
- جدول الحجوزات: العميل، الباقة، تاريخ السفر، عدد الأفراد، المبلغ، المدفوع/المتبقي، الحالة
- إنشاء حجز جديد وتغيير حالته (مبدئي، مؤكد، مدفوع، ملغي)

**الفرص والمتابعات**
- لوحة مراحل بيع (جديد → تواصل → عرض سعر → تفاوض → مغلق) مع سحب البطاقة بين المراحل
- تذكيرات متابعة بتاريخ ومسؤول لكل فرصة

**الموظفون والصلاحيات**
- قائمة الموظفين: الاسم، الدور، البريد، الحالة (نشط/موقوف)، عدد الحجوزات والمبيعات المحققة
- الأدوار: مدير (كل شيء)، مدير مبيعات (الباقات والحجوزات والفرص وتقارير الفريق)، موظف مبيعات (عملاؤه وفرصه وحجوزاته فقط)، محاسب (الحجوزات والمدفوعات للقراءة)
- إضافة موظف وتغيير دوره وإيقافه، وإسناد العملاء والفرص لموظف معين
- في المرحلة التجريبية: مبدّل "الدخول كـ" لتجربة كل دور، والقوائم والأزرار تظهر وتختفي حسب الصلاحية

كل البيانات في هذه المرحلة تجريبية داخل التطبيق (تتغير أثناء الاستخدام لكنها لا تُحفظ بعد إعادة التحميل).

## المرحلة الثانية: الحفظ الدائم وتسجيل الدخول

تفعيل قاعدة بيانات Lovable Cloud وحسابات دخول حقيقية للموظفين، مع تطبيق الصلاحيات على مستوى قاعدة البيانات (جدول أدوار منفصل) لا الواجهة فقط، ونقل كل الشاشات للعمل على بيانات محفوظة. مطلوبة قبل أي ربط خارجي لأن العملاء القادمين من واتساب والموقع يحتاجون مكان تخزين.


## المرحلة الثالثة: الربط مع واتساب وووردبريس

- **واتساب**: استقبال رسائل العملاء وإنشاء عميل/فرصة تلقائياً داخل النظام، مع عرض المحادثة في صفحة العميل. يحتاج حساب WhatsApp Business API (مثل Meta Cloud API أو Twilio) — سأطلب منك بيانات الربط في وقتها.
- **ووردبريس**: سحب الباقات والطلبات من موقعك عبر ربط جاهز، وتحويل كل طلب إلى فرصة أو حجز داخل النظام. أحتاج رابط الموقع وصلاحية دخول للربط.

## التفاصيل التقنية

- TanStack Start + Tailwind، `dir="rtl"` وخط عربي واضح، تنسيق عملة وتواريخ بالعربية
- صفحات منفصلة: `/` (المؤشرات)، `/packages`، `/customers`، `/customers/$id`، `/bookings`، `/pipeline`، `/team`
- تخطيط مشترك بقائمة جانبية يمينية + شريط علوي
- الرسوم البيانية بـ Recharts، الجداول بمكونات shadcn، حالة تجريبية عبر مزوّد React واحد يسهل استبداله لاحقاً بقاعدة البيانات
- الربط مع ووردبريس وواتساب سيتم عبر دوال خادم فقط (المفاتيح لا تظهر في المتصفح)
